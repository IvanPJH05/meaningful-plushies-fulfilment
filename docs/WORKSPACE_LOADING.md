# Workspace loading: second phase

The main dashboard previously launched 18 supporting reads after orders loaded, regardless of the visible workspace. The shared loader now declares each workspace's dependencies and loads only those tables. Ordinary admin fulfilment loads manual-order classification, processor settings, sales fees and creator profiles; accounting, content, history, Meta logs and font settings wait until needed. Existing creator sample code migration/refresh remains in place because sales classification depends on it.

Successful support reads stay cached for the signed-in session. Overlapping callers share in-flight requests. Realtime invalidates changed tables; hidden tables wait until navigation rather than refetching immediately. Changes during an in-flight read cause a fresh read before that table is marked current. Post-mutation refreshes invalidate hidden dependencies but only fetch the active workspace. Focus/visibility and five-minute recovery refreshes also fetch active support data and skip hidden tabs. Failed reads remain retryable, retain existing state and show a visible Retry action.

Dependencies include stock settings for inventory purchase mutations, accounting transactions for offline character sales in stock counts, and envelope settings for staff printing. The Monthly Journal, Our Link and Audio Scanner components now have separate dynamic bundles. Their own internal loaders remain responsible for their data. The generic shared-data/realtime/polling effects no longer start before a session exists.

Validation: TypeScript, ESLint (no errors; existing warnings remain), 68 Node tests, production Next build, and a browser fixture using the actual page loader hooks. Fixture checks covered the first four support reads, Content's two reads, cached return navigation, hidden realtime invalidation, refresh on entry and failure/retry recovery. Reported first-load JavaScript changed from 316 KB on the preceding save-fix build to 296 KB on this build using the same installed dependencies. This is a build-size comparison, not a measured live response-time improvement.

This change is stacked on the order-save fix in PR #151. No production writes or database migration are included. A signed-in deployment smoke test still needs to cover every workspace and mutation path. Existing order summaries/page loading remain in place; server aggregate reporting, historical media migration and consolidation of legacy whole-order writers remain separate follow-up work.
